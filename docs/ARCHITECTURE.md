# Architecture

This document is the contract for the native port. Every agent and contributor follows it.
If you must deviate, write the reason here first (and tell the architect).
Before integration work, read docs/INTEGRATION_NOTES.md (cross-module problems found by module agents).

Companion documents:

- `docs/BUILD.md` — exact setup, build, run and test commands.
- `docs/MODULES.md`, `docs/modules.tsv` — the work modules (generated by `scripts/modules.py`).
- `docs/LIBRARY_CALLS.md` — XBE library functions the game calls, and their replacements.
- `docs/STATUS.md` — what builds and runs today.

## 1. Goal and non-goals

- Goal: run Fuzion Frenzy (Blitz Games 2001, codename BlitzParty) natively on Apple Silicon
  macOS (arm64), from decompiled C.
- Functional decompilation. We do not try to match the original bytes.
- No emulator, no x86 translation at run time. The XBE is an input for analysis only.
- No game data in git. The player supplies `orig/game.xiso.iso` (their own disc image). The game
  reads it directly; nothing is extracted.

## 2. Overview

```text
+--------------------------------------------------------------------------+
| guest image  openfrenzy_guest.elf  (arm64_32: 32-bit pointers and long)   |
|                                                                          |
|  src/<game and engine modules>   decompiled C, original struct layouts   |
|  gen: of_decls.h, of_stubs.c (weak stubs), of_crt_init.c                 |
|  src/runtime  boot, stubs, sdl_platform, config, XDK headers   \         |
|  src/vfs      D: drive on the disc image (XDVDFS)               |        |
|  src/xkernel  kernel + XAPI HLE                                 | XDK    |
|  src/d3d8     Direct3D 8 on GLES 3, NV2A shaders, swizzle       | layer  |
|  src/dsound   DirectSound on SDL3 audio, WMA, Bink on FFmpeg    | (HLE)  |
|  src/input    XInput on SDL3 gamepad/keyboard                  /         |
|  port/guest/runtime  musl start, threads, SDL/GL/posix wrappers          |
|  musl 1.2.5 (libguestc.a)                                                |
|  every file: clang -emit-llvm -> opt (of-rebase) -> llc -> ELF object    |
+-------------------------- host imports (host_*, hostgl_*, hostposix_*) --+
| Darwin host  openfrenzy  (native arm64, Apple clang)  port/macos/host     |
|  loader, 4 GB arena, threads/futex, syscalls -> Darwin, files            |
|  SDL3 (window, events, gamepad, audio), GLES 3 via ANGLE on Metal        |
+--------------------------------------------------------------------------+
```

The game code is compiled as a **guest** with 32-bit data layouts. A small native **host**
provides the operating system. This is the OpenCE design (Halo: Combat Evolved port), reused
instead of invented (section 14 lists what came from where).

## 3. Why a 32-bit-layout guest

The Xbox game stores pointers in 32-bit struct fields, file formats and packed arrays. Ghidra's
output assumes `sizeof(void *) == 4` and `sizeof(long) == 4`. A normal arm64 Mac process (LP64)
cannot keep these layouts, and macOS does not map the low 4 GB for user code.

- The guest is compiled for the LLVM target `arm64_32-apple-watchos` (ILP32 on AArch64), with
  the Darwin environment hidden (`-U__APPLE__ -D__linux__`); its C library is musl.
- Pointers are 4 bytes, `long` is 4 bytes, and struct offsets are the original ones. Decompiled
  structs copy Ghidra's offsets directly. Do not "fix" them to 64-bit.
- `src/include/of_types.h` asserts `sizeof(void *) == 4` in every game file.

## 4. Guest compiler: LLVM 22 plus `of-rebase`

Homebrew `llvm@22` and `lld@22`. The pass needs **LLVM 22** (Apple clang and LLVM 23 are not
supported for the guest; Apple clang builds the host). `port/macos/tools/guest_cc.py` runs, for
each guest file:

1. `clang --target=arm64_32-apple-watchos -emit-llvm` (IR with 4-byte pointers),
2. `opt -load-pass-plugin=guest_rebase.dylib -passes=of-rebase,verify`,
3. `llc -O2 -mtriple=arm64_32-apple-watchos -emulated-tls`,
4. `asm_convert.py` (Mach-O assembly to ELF assembly), then `clang --target=aarch64-none-elf -c`.

`ld.lld` links one static ELF image at `0x88000000` (`port/macos/guest.ld`).

The pass (`port/macos/compiler/guest_rebase.cpp`) sends every load, store and indirect call
through a 64-bit pointer in LLVM address space 272, computed as `BIAS | (uint32_t)ptr`. It lowers
varargs and memory intrinsics, and gives declarations named `host*` 64-bit pointer parameters so
the host receives real addresses (opaque GL handles keep 32 bits). It checks pointer size 4 and
fails the build otherwise. It is an ABI adapter, not a sandbox.

Known trap (from OpenCE): ILP32 instruction selection can add the bias twice when it splits an
unaligned 64-bit load from a stack pointer. The pass keeps OpenCE's machine-level fix.

Known trap (openfrenzy): code runs at BIAS + address, so `adrp`/`add :lo12:` give biased global
addresses, but LLVM's ILP32 known-bits say their upper 32 bits are 0. The pass therefore sends
every value use of a global address (not load/store addresses or direct callees) through an
opaque `mov wD, wS`. Test: `guest_adrp_runs`.

Every guest C object depends on `guest_rebase.dylib` and `port/macos/tools/*.py`
(`guest_cc.py` appends them to the compiler's depfile), so a toolchain change rebuilds the guest.

## 5. Memory: the 4 GB arena

- The host reserves a 4 GB **virtual** arena at `0x10000000000`. A guest address `p` is host
  address `0x10000000000 | p`. Guest address 0 stays NULL; the low 16 MB stay unmapped.
- Reservation is not RAM use; pages are committed on demand. macOS pages are 16 KB, Xbox pages
  4 KB; the host combines protection for 4 KB allocations that share a 16 KB page.
- Layout (`port/macos/include/openfrenzy_guest_abi.h`): Xbox contiguous-memory window
  `0x80000000-0x88000000` (D3D resources, `MmAllocateContiguousMemory`), guest image at
  `0x88000000`, guest heap and stacks from the host's low mappings.
- Original XBE addresses are **not** guest addresses. Code is recompiled; an original address
  survives only in comments, in symbol names (`FUN_0002cd80`) and in tables that we rebuild
  with symbols (vtables, jump tables). Never put an original address into a pointer.

## 6. Darwin host (`port/macos/host/`)

From OpenCE-mac-zimm3rmann (`e55684a`), renamed `HALO_*` -> `OPENFRENZY_*`:

| File | Job |
|---|---|
| `entry.s`, `host_loader.c` | Load the guest ELF into the arena, fill its import table, enter it on a guest stack. |
| `host_main.c` | Process start, data/save roots, signal handlers. The guest runs on the real main thread. |
| `host_memory.c` | Arena, 16 KB / 4 KB page sharing, write tracking for textures. |
| `host_thread.c` | Threads, futex, TLS for guest threads. |
| `host_syscall.c`, `host_errno.c` | musl's Linux syscall ABI translated to Darwin. |
| `posix_files.c` | The file helpers of `src/vfs/posix.h` (`hostposix_*`). |
| `host_sdl.c` | SDL3 window, events, gamepad, audio (guest-side handles). |
| `host_gl.c`, `host_gl_bridge.c` | GLES 3 entry points (`hostgl_*`), implemented by ANGLE. |
| `host_perf.c` | Frame timing log. |
| `host_bink.c` | Bink video and audio decoding with FFmpeg (`host_bink_*`; openfrenzy, not from OpenCE). Without FFmpeg (`OPENFRENZY_BINK_FFMPEG` off) every open fails. |

- Window, input and audio use **SDL3** (Homebrew 3.4.x). Rendering uses **GLES 3.0** from
  **ANGLE with the Metal backend** (pinned download, `port/macos/dependencies.json`).
- `OPENFRENZY_WINDOWED=1` gives a window; otherwise borderless fullscreen.
- Audio mixing runs on a guest-stack worker; results go to SDL's callback thread (avoids
  OpenCE's stream-lock deadlock).
- Added for this game (the OpenCE layer at `231708d` is newer than the Mac host):
  `host_gl_read_buffer`, `host_memory_watch_begin_frame`, `host_sdl_destroy_audio_stream`
  (pauses only), `host_sdl_scancode_from_name`, `host_sdl_scancode_name`.
- A new host function needs: the host definition, a line in `port/macos/host_imports.list`, a
  declaration in `port/guest/runtime/guest_host.h`. Only the runtime module (architect) adds them.

## 7. Boot chain

On the Xbox (from `entry` and Ghidra):

```text
entry 0x00030f7f            sets TLS size; CreateThread(mainXapiStartup); XapiBootToDash on failure
mainXapiStartup 0x00030f10  XapiInitProcess, _rtinit,
                            _cinit 0x000340f8: .CRT$XI table (LIBC) at 0x002818a4,
                                               .CRT$XC table (81 game static constructors) at 0x00281750
                            main 0x0002d540, then XapiBootToDash
main 0x0002d540             FUN_0004e690(core_init 0x0002cd80, 0) (bKernel), then an endless loop
core_init 0x0002cd80        XMountUtilityDrive, memory statistics, Babel heaps (FUN_0004b160),
                            new CPCSystem, screen, GUI, game state (FUN_0002fa20), packages,
                            then the game-mode loop (core.cpp)
```

In the port, `src/runtime/of_boot.c` is `main()`: it runs `of_run_static_constructors()` (the 81
constructors at `0x001f29f0-0x001f4e20`, generated in `.CRT$XC` order) and then calls
`FUN_0002d540`. XAPI start-up, `_rtinit` and the LIBC initialisers are replaced by musl and the
platform layer, which starts itself on first use (`platform_sdl_initialize`).

Boot order for decompilation: `core` (main, core_init, the mode loop, static constructors),
`bkernel` (heaps, files, packages, the task/thread start `FUN_0004e690`), `bdisplay` (D3D device,
textures), `engine_misc` (input, sound), `bactor`, then the front end (`core_modes_*`,
`classlib_*`, `charlib`), `meta_*` (the board game), and the minigames.

| Files | What | Port |
|---|---|---|

| `Packages/Music.xbp` (37 MB) | 29 WMA (ASF) streams; `InitMusic` "%s.wma" (0x00071b60) | `wma_decoder.c` (port of FFmpeg's WMA v1/v2 decoder) |
| `Packages/MetaLevs/*.lnd` | text level scripts for the board game (`LANDSCAPE sitemesh01.obe 0 0 0`, `PLAY_TIME 4800`); parsed by `Meta/LevelLoad.cpp` (0x00166db0) | meta |

## 9. Platform layer (XDK replacement)

The XBE links the XDK statically. We do **not** decompile it. Each part is replaced by the OpenCE
equivalent (`ref/OpenCE/port/linux/src/` at `231708d`), split into platform modules:

| XBE section / region | Replaced by | Module |
|---|---|---|
| `D3D` (D3D8 1.0.3925), `XGRPH` | `d3d8_gl.c`, `d3d8_resources.c`, `nv2a_vsh.c`, `nv2a_psh.c`, `xbox_textures.c`, `gl_functions.c`, `xgpu_text.c`, `xgpu_post.c` | d3d8 |
| `DSOUND` (3925) | `dsound_sdl.c` | dsound |
| `WMADEC`, `WMADECXM` | `wma_xmo.c` (`WmaCreateDecoder`) on `wma_decoder.c` (port of FFmpeg n4.4.4 WMA v1/v2) | dsound |
| `.text` region `bink` (RAD Bink) | `bink_host.c` (started from OpenCE's `bink_null.c`): the host decodes with FFmpeg (`host_bink.c`); audio goes to a DirectSound stream | dsound |
| `XPP` | `xinput_sdl.c` | input |
| `.text` regions `xapi`, `libc` | `xbox_kernel.c`, `xbox_xapi.c`, `xbox_memory.c` + musl + `msvc_crt.c`/`msvc_wide.c` | xkernel, runtime |
| disc and save drives | `xiso_fs.c` (new: XDVDFS reader), `xbox_files.c`, `xiso.c` | vfs |
| `DOLBY` | nothing (DSP microcode, unused with SDL audio) | - |
| `.text` region `eh_funclets` | nothing (C++ exception unwind funclets; the port has no C++ exceptions) | - |

`src/runtime/entry/xdk_entry_points.inc` maps each `D3D`/`DSOUND`/`XGRPH`/`XPP` function to its
HLE function (`HLE`, `MISSING`, `UNKNOWN`, `INTERNAL`). `docs/LIBRARY_CALLS.md` lists every
library function the game calls (192: 75 libc, 27 xapi, 52 D3D, 23 DSOUND, 7 XPP, 4 XGRPH,
3 Bink, 1 WMA) with its replacement. Decompiled code calls the replacement by its XDK or C name
(`D3DDevice_SetTransform`, `IDirectSoundBuffer_Play`, `CreateMutexA`, `sprintf`), never the address.

Platform rules:

- Platform code includes `platform.h` and the XDK headers in `src/runtime/include/xdk/`
  (OpenCE's clean-room declarations: `xtl.h`, `xdk_d3d8.h`, `xdk_dsound.h`, ...). We have no XDK.
- Only platform code calls SDL, GL or `host_*`, and only through the guest runtime wrappers in
  `port/guest/runtime/` (an SDL function missing there needs a host import: ask the architect).
- `openfrenzy_platform_check.elf` links every platform object; an undefined symbol fails the build.
- `src/vfs/posix.h` is shared with the host (`posix_files.c`); change it only with the architect.

## 10. Source layout and language

```text
src/
  include/      of_game.h, of_types.h, of_functions.tsv   (architect only)
  runtime/ vfs/ xkernel/ d3d8/ dsound/ input/             platform modules
  <module>/     one directory per game/engine work module (docs/MODULES.md), e.g.
    core/Core/core.c                 <- C:\BlitzParty\Game\Src\Core\core.cpp
    bkernel/bKernel/file.c           <- C:\Babel\Xbox\Src\bKernel\file.cpp
    meta_a/Meta/unplaced.c           <- gap functions of Meta without a known file
    core.decls                       <- prototype overrides (section 11)
port/guest/   guest CMake project, guest runtime, musl arch headers
port/macos/   host, compiler pass, build tools, tests
scripts/      analysis (Ghidra scripts, map_sources.py, modules.py, gen_*.py, xbe_data.py)
```

- **Language: C (gnu11).** The game was C++, but Ghidra's output is C, the stubs and declarations
  need unmangled names, and the reused toolchain and platform layer are C. Methods become
  functions with an explicit `this` first parameter; virtual calls go through function-pointer
  tables (section 12). Do not use C++.
- A function goes in `src/<module>/<OrigDir>/<File>.c`, where `<OrigDir>/<File>` is its original
  source file (`file` column of `src/include/of_functions.tsv`, from `export/source_map.json`),
  with `.cpp` changed to `.c`. Functions without a file (`-` in the table) go in
  `src/<module>/<OrigDir>/unplaced.c` (`dir` column); move them when you learn their file.
  `LIB:crt_init` and `LIB:crt_exit` (static constructors/destructors) go in
  `src/core/crt/static_init.c` until you know the global they construct.
- Module headers: `src/<module>/<module>_<topic>.h` (file names must be unique across `src/`,
  since every module directory is on the include path). Another module may include your header;
  only you edit it.
- The module of a function is fixed by the table (`module` column), not by its file path.

## 11. Function table, declarations and stubs (how the build always links)

`src/include/of_functions.tsv` (generated by `scripts/gen_function_table.py`, committed) lists all
**5623** game and engine functions: address, module, source file, directory, confidence, size,
static-constructor order, Ghidra name and a prototype in Ghidra types. At build time
`port/macos/tools/gen_game_decls.py` makes:

- `of_decls.h` (force-included through `of_game.h`): a prototype for every function, named
  `FUN_<addr>`. Every game file sees every function. Call others by `FUN_<addr>` or by the name
  their owner gave (both work).
- `of_stubs.c`: a **weak** definition of every function that logs
  `UNIMPLEMENTED 0x<addr> <name> (#n)` once and returns 0. When you define the function (a strong
  symbol), yours replaces the stub at link time. So the image always links, and the log shows the
  next functions to write. `OPENFRENZY_STUB_ABORT=1` stops at the first stub;
  `OPENFRENZY_STUB_LOG=all` logs every call.
- `of_crt_init.c`: `of_run_static_constructors()`, in the original order.

**Prototype overrides.** Ghidra's prototypes are guesses (a `float` parameter may show as
`undefined4`, `float10` returns are shown as `float`). Callers compile against the table's
prototype, so a wrong one is an ABI bug (float and integer arguments use different registers).
When you decompile a function, put its true prototype in your module's `.decls` file:

```text
# src/core/core.decls  -  <addr> <prototype>;
0002cd80 void Core_Init(void);
00027f10 int CGameMode_Root_Pushed(struct CGameMode_Root *self, int mode);
```

- Use only `of_types.h`/C types and `struct Name *` in a `.decls` line (no typedefs from your headers).
- A new name makes `FUN_<addr>` a macro for it. The generator rejects an address that belongs to
  another module, an unknown address, or a duplicate (the build fails with the reason).
- Define the function with exactly that prototype.
- `gen_game_decls.py --table src/include/of_functions.tsv --src src --check` validates quickly.

Functions not in the table (Ghidra missed them; you find one through a vtable or a call): export
it with `scripts/ExportAt.java` (section 13), define it in your module with its `FUN_<addr>` name
and a prototype in your own header, and list it in your final report so the architect adds it
to the table. Do not edit `of_functions.tsv` yourself.

## 12. Rules for decompiled code

- **Each function keeps a comment with its original address and source file:**

  ```c
  /* 0x00027f10  Core/CGameMode_Root.cpp */
  int CGameMode_Root_Pushed(struct CGameMode_Root *self, int mode)
  ```

  `scripts/coverage.py` counts `// 0x<addr>` or `/* 0x<addr>` comments followed by a body. A
  body that calls `of_unimplemented`/`PLATFORM_UNIMPLEMENTED` or says `STUB` counts as a stub.
  Data with a known original address (globals, vtables, tables) gets the same comment.
- **Layouts**: keep Ghidra's offsets. For structs read from files or shared with the platform
  layer, add `OF_ASSERT_SIZE(struct X, 0x..)` and `OF_ASSERT_OFFSET(struct X, field, 0x..)`.
- **Types**: Ghidra's names (`undefined4`, `uint`, `byte`, `float10`, `code`) are typedefs in
  `of_types.h`; replace them with real types as you understand the code. `CONCAT*`, `SUB*`,
  `ZEXT*`, `SEXT*` macros exist.
- **Calls through `code *`**: `typedef int code();` is unprototyped. If an argument or the result
  is a float, cast to a real function-pointer type (`((void (*)(void *, float))fn)(obj, 1.0f)`),
  else the float is passed as a double in the wrong register.
- **x87**: `float10` is `double`. Functions that returned `float10` in ST0 usually return `float`:
  fix the prototype in your `.decls`. `_ftol` (`FUN_001de998`) is a C cast.
- **Globals**: write them with their Ghidra names (`DAT_002ba9a0`) or better names. An
  uninitialised global may be defined in several modules (`-fcommon` merges them; give the same
  type and size). An initialised global is defined by one module: the owner of the code that
  initialises or mainly uses it; others declare it `extern` through the owner's header.
- **Vtables and tables**: rebuild them from the XBE with symbols:
  `python3 -I scripts/xbe_data.py vtable 0x0026f038` prints `static const void *const
  vtable_0026f038[] = { (const void *)FUN_0014b6c0, ... }`. Constructors store `vtable_xxx` into
  the object's first word. `xbe_data.py floats|dwords|bytes|string ADDR [N]` prints other data.
  Never copy an original pointer value.
- **Library calls**: see `docs/LIBRARY_CALLS.md`. Include `<stdio.h>`, `<string.h>`, `<math.h>` (musl)
  and `"xtl.h"` (XDK types, D3D, DirectSound) as needed. C++ helpers: `operator new` is the
  Babel allocator `FUN_0004c480(size, file, line, flags)` in this game (bKernel); the array
  constructor/destructor iterators become loops. (`FUN_0004c480` and the matching free
  `FUN_0004c110` are read from core_init and a deleting destructor; the bkernel agent confirms.)
- **SEH**: `__try`/`__except` compile (the prefix header maps them); the handler never runs.
- **No host, SDL or GL calls** in game or engine code. Use the XDK API (it is the platform's job).
- **Names**: keep `FUN_<addr>` until the purpose is clear, then rename through `.decls`. Name
  methods `Class_Method` (`CGameMode_Root_Pushed`).
- **Sources for decompilation**: `export/funcs/<addr>.c` (Ghidra C) and
  `export/functions.jsonl` + `export/functions_extra.jsonl` (callers, callees, strings).

| `python3 -I scripts/map_sources.py` | `export/source_map.json`: source file per function (tagged, bracketed, vtable, gap) and library regions |

Ghidra runs headless and read-only (`docs/BUILD.md`). It writes `~/Library/ghidra`, which the
sandbox blocks: run it outside the sandbox. Never run two Ghidra processes that write the project.

Source map quality (5623 game/engine functions after the vtable pass): 461 tagged by an assert
path, 829 bracketed between two tags of one file, 355 by vtable membership, 3711 in gaps (a
directory or two candidate files are known, the file is not), 76 leading/trailing, and 191 in
the `crt_init`, `crt_exit` and `engine_tail` regions. Ghidra's first analysis missed about
1280 functions reached only through tables (virtual methods, static constructors);
`export/functions_extra.jsonl` holds them.

## 15. Rules for parallel work

- One agent = one module = one directory `src/<id>/`. Edit only files in your directory. Adding a
  header in your directory is fine. Shared files (`src/include/`, `port/`, `CMakeLists.txt`,
  `scripts/`, `docs/ARCHITECTURE.md`) belong to the architect: ask, do not edit.
- Build in your own directory: `cmake -S . -B build-<id> -G Ninja && cmake --build build-<id>`.
- Before you commit: the build passes and `ctest --test-dir build-<id>` passes.
- Commit only your own paths (`git add src/<id>`), never `git add -A`. If `.git/index.lock`
  exists, wait and retry.
- Never commit game data, the XBE, the ISO, `export/` or build directories.
- In your final report: what you finished, what you could not verify, functions you found that
  are missing from the table, library functions you identified, prototype changes others must know.
